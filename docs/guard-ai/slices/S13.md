## Choices
- Stage gear lives on the manager (`alarmGear`), so every later spawn path gets it with no extra call: `placeSlot`
  (section guards, reinforcements, any map mode) and `revive`. Sector Ops sets it at each load and each rise; other
  modes never set it (stage 0 = none; their one alarm counts as stage 1 = none). S12-CHECK's note holds: the gear is
  added after `placeSlot`'s own `setGear`, inside it.
- The rise gives the gear to every living guard (Sector Ops has only the live section loaded); down guards get it when
  woken. A guard whose helmet was shot off gets one back at the stage 3 rise (A52).
- Team order = pending order: the enforcer is pushed first and `fill` spawns in order (a live-cap stop keeps the
  order). Kinds past `responseTeam`'s count (none today) fall back to `SECTOR_REINFORCE_KIND`.
- The sweep is a team state, not an alert level: members stay `searching` (S6 hunting: never calm), so perception,
  torches, the HUD and the ghost read it as a search. A sighting puts the leader in combat, `tick` drops the sweep, and
  the next search that runs its full 60 s switches it on again with a fresh order from the new LKP (A53).
- Each pass starts at the team's start point (A54). Followers stack on the leader's approach line (A55).
- No camera code is touched: `raised` still only sets `ct.alarm` (shown by the devices); the unit test checks the
  camera list, states and calls, the e2e the live camera list and modes.
- Per-step code allocates nothing new (`tick` loops by index; `sweepStep` writes a reused goal and point); `goTo`'s A*
  replan is the existing path code every walking guard uses.

## e2e-levels ladder flake
- Symptom: under load (full run, `E2E_JOBS=3` beside another run) "a runner climbs the rack ladder to the player" failed with "0.0 -> 0.02 m in 30 s"; alone it passes (2.80 m climbed).
- Cause: not a wall-clock wait. The chase was already on the manual clock (`stepHeadless`) with a seeded `Math.random` and a 30 s of game time cap. What moved with load was the world state when the clock took over: the match ran real-time sim steps until the first poll and through `frames(page, 10)`, and a loaded machine ran a different number of them, so the runner started from a different world. Solo runs already read 10 to 15.5 s of game time, so a bad start had no margin.
- Fix (`scripts/e2e-levels.mjs:15-23` the takeover, `:47` the settle, `:49-91` the chase): `loop.manual` is set inside the first `waitForFunction` poll that sees the match (no real-time sim steps follow), then 2 sim s settle. Each chase steps 0.25 sim s until a link was taken, the runner is off it and within 0.4 m of the player's storey, or a sim budget ends it. Budget = 4 x ideal + 30 s, ideal = 7.2 m at the runner's run speed (`def.runSpeed` 4.2) + rise / climb speed (up 1.1, down 1.4 m/s, `Enemy.runLink`): about 4.5 s ideal, 48 s up, 45 s down (solo reads 10 to 15.5 s). A 240 s wall cap is only the hang guard. The assert text keeps its meaning and prints sim seconds, the budget, wall seconds and, on a miss, the runner state.
- Not run (no e2e by order): `node --check` only. If it still fails under load, the failure line now names the runner's state and link, which says whether the runner never saw a ladder route or was still climbing.
