## Choices (new assumptions A60-A64 in BRIEF.md)
- A60: the walk is calm (no level change; suspicious only from a glimpse, then it carries on); a spoken bark, no radio
  call; the other witnesses ack (look 3 s, up to 2 "Copy.").
- A61: the repeat clock runs from the last cut a guard noticed (a witness or a late find), board clock; an unseen cut
  starts nothing.
- A62: late discovery uses the focused cone only (no peripheral field) within 12 m, calm free guards only, one ray.
- A63: only a cut at a switch is a fault. A circuit dark with its switch still on (an isolator that leaves the switches
  alone) keeps the S2 light incident, and so does a course mains gate's circuit (no guard relights it and shuts the gate); the walk ends as soon as any lamp of the circuit is lit again at
  its base. marlow-final's timed isolator (`isolate`) is not on this branch: when it lands, it gets the breaker walk and
  the walk's end by calling `StealthSystems.syncGroup(group, false)` when it cuts and `syncGroup(group, true)` when it
  relights (or keep the S2 incident, which is today's behaviour).
- A64: the stand point, 0.7 m reach, 30 s give-up, patrol pace.
- Shot lamps: no code change: `LightRegistry.setGroup` skips destroyed lamps, so a guard's reset never relights one; a
  test pins it.

## Hot path
`lateStep` runs every 0.1 s; per tick at most `ceil(N x 0.3)` guards x the short dark list (usually empty: the pass
returns at once); one ray only when a fixture is in range and in the cone. `DarkList.refresh` is O(lights) and runs only
when the registry's `version` moved. `breakerStep` per walking guard per step: one `isOff` (a loop over the switches and
the circuit's lamps), no allocation (the goal object is reused). Every loop is an indexed `for`.
