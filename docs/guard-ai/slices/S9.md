## Choices (BRIEF A90-A95; A80-A89 left for S16)
- A90: barks by index, with pair talk and the desk's camera line as text (the design-12 proposal named only indices;
  pair tables can be map-specific, so the index is not enough there).
- A91: a host caution stance did not exist (caution posed as calm, 0.2). Low ready 0.4 is added on both sides, so the
  "caution stance matches" row holds; the wire level 1 shows investigating's 0.7.
- A92: the client's helmet drop direction (own round within 1 s, else backwards); a jump over 1.5 m in one frame is a
  re-place and drops nothing.
- A93: the client predicts the deflect from the bits (the marker and ping through the same `playerWeapons` /
  `hud.hitMarker('deflect')` / `sfx.hitMarker('deflect')` path the host uses); the host's confirm fills in only an
  unpredicted one.
- A94: the puppet also predicts the enforcer's front shield block (0 dealt), as the host's `shieldBlocks`.
- A95: one gear builder for both sides (no change in look).
- S15 relight: no code. A guard's reset flips the registry through `StealthSystems`, so the existing `lamps` message
  (Sector Ops, `LampSender` on registry version) and `course.lights` carry it; the client's switch labels still do not
  follow it (S15 open item, same as a host press).
- Hot paths: nothing per snapshot allocates (`alertCode` packs booleans; `applyGear` runs only on a gear-bit change and
  builds parts once; `barkAt` is a map lookup into a kept vector). Bark events allocate one small object per line
  (lines are rate-limited by `BarkVoice`, as the host's own HUD path). `EnemyPuppet.gearShown` allocates (tests only).
- Single player: no new static `src/net` import (`gameState` calls the optional `net.barkAt`); `src/ai` imports nothing
  from `src/net`.

## e2e (written, not run)
`scripts/e2e-coop.mjs` block "guard-ai S9: stage gear, a bark, caution, a shield-led team and a deflect on the client"
(after the client kill, before "downed and revived"): `setAlarmStage(3)` -> the puppet shows helmet and armour; a host
guard's `bark('missed', 3)` -> the client shows the same text; a timed section caution on a keyed guard -> the
puppet's `cautious`; a shield-led team (`newTeam` + `spawnReinforcement` enforcer, grunt, grunt + `joinTeam`) -> the
client's enforcer shows shield and helmet, then the team is despawned and the stage set back to 0 (no `now`); a client
head round on the helmeted guard (moved to the open floor, the client 2.2 m north, drawn) -> predicted deflect (0
dealt), the host's guard alive without his helmet and a drop on the host floor, `deflectConfirms` >= 1, the puppet's
helmet off and a drop on the client floor.

Risks:
- The team spawns at (12-14.4, 0, -6.5) on the Warehouse (the earlier block's open floor); a spawn refused there fails
  `team.length === 3`.
- The caution step reads `em.awareness.timedHold` and the private `syncCaution`; with no keyed guard it logs and skips.
- After `setAlarmStage(3)` every guard of that match keeps armour and a helmet for the rest of it (downed / revive,
  malformed, rejoin, team wipe do not shoot guards; the next match is a new manager).
- The deflect staggers the guard (0.9 s) and puts him in combat; the players are invulnerable there (damageMul 0).
- e2e-netmove: no assertion reads the puppet's aim; the puppet now raises to 0.7 when searching (was 0.2 unless `st`).
- Suites to run (laptop, `E2E_GPU=1`): e2e-coop, e2e-netmove (src/net, src/game changed), and e2e-stealth-ai /
  e2e-takedown (enemy.ts gear builder moved, the host's caution pose).
