## Steps
1. Registry (`src/world/lights.ts`): `LightDef.failed: boolean` (init `false` at `:188-190`). New
   `fail(id): boolean`: for a fixed light (not `kind === 'flashlight'`) not already failed, set `failed = true`,
   `destroyed = true`, `on = false`, drop any `outFor` / jam entry for it, `version++`, return true. No `destructible`
   check and no shot cue. `restore` (`:387-399`) and `resetTo` (`:407-424`) return at once for a failed light (it stays
   dark through a section or course restart). `destroy` and `kill` leave a failed light alone. Check every other method
   that sets `on` or `destroyed` (`setOn :238`, jam paths `:329-358`, `setGroup :361`, `kill :428`, `disrupt` / `update` outage paths `:437-470`) keeps a failed
   light dark; add a one-line guard where one could relight it.
2. Baker (`src/voxel/sectionJobs.ts`): `onFailed(fn: (lamp: number) => void)` (listener list, like `liveListeners`);
   `retryInline`'s catch (`:375-377`) calls the listeners with the lamp index after `failed++`. Keep the log and the
   no-cache rule.
3. Bake (`src/world/lightBake.ts:108-110`): after `new SectionBaker(...)`, `sb.onFailed((i) => inp.reg.fail(baked.ids[i]!))`.
   This runs in every mode (solo too: the glow goes dark with the light).
4. Lamp sync (`src/net/lampSync.ts`): `LAMP_FAIL = 3`; `lampState` returns it first when `l.failed`; `LampWire.fl?:
   string`; `encodeLamps` adds `fl` only when a state is `LAMP_FAIL`; `decodeLamps` reads `fl` first (failed, then shot,
   then off); `applyLamps` calls `reg.fail(i)` for `LAMP_FAIL` (no `onShot`), and a light already failed here stays
   failed whatever the wire says (`resetTo` already refuses). `LampSender` sends on the version bump `fail` makes. No
   allocation in read / compare / apply.
5. Wire (`src/net/protocol.ts`): `lamps` (`:341-342`) gets `fl?` (parser `:1037-1042`: same `LAMP_BITS` and
   `LAMP_CHARS` checks as `of`, dropped when bad). New client -> host variant `{ t: 'lfail'; ids: number[] }`: parser
   keeps 1-8 unique integers in `0..LAMP_MAX-1`, else null. Do not touch `PROTOCOL_VERSION`.
6. Session (`src/net/session.ts:205`): add `'lfail'` to the client messages the host passes on as `game`.
7. Client (`src/net/coopClient.ts`): once a second (an accumulator in the existing step, no new timer), scan the
   registry for `failed` lights not yet reported (a `Uint8Array` by id, sized once) and send one `lfail` with up to 8
   ids; the rest go next second. No allocation when nothing is new.
8. Host (`src/net/coopHost.ts`): on `lfail` from a player, for each id: skip if out of range, a flashlight or already
   failed; count per player per match (a `Map<string, number>` cleared on a new match); past 8 log once and ignore;
   else `reg.fail(id)` and log once per match "[light-parity] lamp <id> failed on <player>: dark for everyone". The
   next `lamps` send carries `fl`. A host failure needs no message: step 3 marks its registry and `fl` carries it.
9. Docs: `docs/systems/lighting.md:182-184`: "A lamp that fails every way lands dark for this match only" becomes: it is
   marked failed (`LightRegistry.fail`) and is dark on every machine for this match: the host's own failure reaches
   clients in the `lamps` message's `fl`, a client's reaches the host as `lfail` (at most 8 per player per match); logged
   once, never cached.
10. Fragment `changes/feature-light-parity-net.md`: add "Co-op: a light that fails to load on one player's machine is
    now dark for every player, so the light meter and the guards agree with what everyone sees."

  false)`, `setOn(id, true)`, `setGroup` and a jam end leave it dark; a flashlight refuses.

  `:26-28`); `onFailed` fires once with that index and `incomplete` is true.
