## Steps
1. `lib.mjs`: pure `paritySummary(texts)`: from log texts, every line starting `PARITY-SUMMARY ` parsed as JSON (bad
   lines skipped); returns null when there are none, else `{ parts, cards: { ok, total }, meter: { ok, total }, known:
   [...], misses: [...] }` summed over parts (a part seen twice: the last wins). And `parityStatus(sum)`: state
   `success` when `misses` is empty, else `failure`; description `<ok>/<total> cards, <ok>/<total> meter, known <k>`
   plus `, miss <first id>` on failure, cut to 140 characters.
2. `service.mjs`: after a train's verdict (`finish(job, 'laptop-e2e', ...)` at `:1033`), read the shard logs it just
   wrote (`path.join(runDir, \`${p}.log\`)`, as `:1019-1021` name them), and when `paritySummary` is not null post
   `postStatus(train.sha, state, 'parity', description)` (`:195`). Same after a train rerun that ran `e2e-parity` parts
   (`:1253` area). The desktop lane prefixes `desktop: ` as the other statuses do. Never fail the service on a parse
   error (log once).
3. Fragment `changes/feature-light-parity-q1.md` (`kind: patch`): "Laptop queue: each train head gets a `parity`
   status with the light check's counts."

## Tests

of a repeated part; `parityStatus` success / failure text and the 140-character cut.
