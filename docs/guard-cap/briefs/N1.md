## Change
1. `snapRate.ts`: `snapInclude(snapN, slot, near, calm, changed, fresh): boolean`: true when near, not calm, changed or
   fresh; else `(snapN + slot) % SNAP_FAR_EVERY === 0`. No allocation.
2. Host `snapshot()`: a snap counter; per guard: `near` = min squared horizontal distance (`hyp2` terms, no sqrt needed)
   to every player's feet (host + remotes: one broadcast serves all) < `SNAP_NEAR_R`^2; `calm` = `(al & (3 | AL_SEIZED |
   AL_CAUTION)) === 0`; `changed` = `st`, `al` or rounded `hp` differ from the last sent for that id; `fresh` = never sent;
   `slot` stable from the id. Last-sent records in one host Map keyed by id, a record reused per guard, deleted on
   despawn. Skipped guards are simply not pushed. History, events, bodies, host authority: unchanged.
3. Client torch: `get torch()` stays on while `stale <= (SNAP_FAR_EVERY - 1) / SNAP_HZ + 1e-6` (export `SNAP_HZ` or
   restate it beside the constant with a test tying them). A guard really dropped loses his torch within one cadence
   (~0.2 s) instead of at once: write that in the PR.
4. Interpolation: no change. A far guard's states come 0.2 s apart; with the 0.16 s client delay the buffer extrapolates
   at most ~0.05 s, inside its 0.25 s cap. Shots at far guards: the host judges on its rewound history; the client's shown
   far guard is off by < 7 cm at patrol speed. Note it, no fix.
5. PR text: "wire semantics change (guards omitted on a cadence, torch tolerance): the train bumps PROTOCOL_VERSION".
