## Why
The moon / sun shadow is one `CascadedShadowGenerator` whose shadow map draws its whole render list into every
cascade: Babylon has no per-cascade culling (`node_modules/@babylonjs/core/Rendering/objectRenderer.js` 651-760:
`_prepareRenderingManager` takes `renderList` as is, no frustum test; `world.ts:319` says the same: "every cascade draws
its whole list"). At Epic (4 cascades, `src/core/quality.ts:124`) a guard 60 m away is drawn 4 times per shadow refresh,
3 of them into cascades whose area it is not even in. After S1 a guard is one merged mesh (plus its gun), so it is cheap
to cull per caster. Expected (PLAN S6): -0.5 to -1 ms CPU, -1 to -2 ms GPU at 24 guards under open sky. It only
matters where moving casters are in the sun list at all: under the baked moon a caster under a roof is already left out
(`world.ts:351-358`), and at Low the cascades draw nothing moving (`staticSun`, `world.ts:340`).

Two rules, built in this order:
1. **Per-cascade lists (exact, no pixel change, every caster).** Each cascade draws only the casters whose bounding
   sphere (plus a pad) overlaps that cascade's light-space square. A caster outside a cascade's orthographic x / y
   range writes nothing into that layer, so dropping it changes no pixel. Depth is ignored (`csm.depthClamp = true`,
   `world.ts:598`: casters in front of the near plane are clamped, so they still count).
2. **Guards beyond `GUARD_SUN_REACH` (40 m) from the camera leave the sun list (a small, intended look change).**
   Only meshes registered with a reach (guards and their guns, from `src/ai/enemyRig.ts`) are affected; the player,
   partners, dummies, VIP, props and bodies keep `Infinity`. Hysteresis 3 m (in below 40 m, out above 43 m) so a guard
   pacing at the line does not flicker. At Epic the cascade splits are about 6 / 13.5 / 29 / 90 m of view depth
   (lambda 0.75, `shadowMaxZ` 90, `world.ts:589-591`), so 40 m keeps every guard in cascades 0-2 and drops it only from
   the coarse far slab. Note: while sun shadows are on, the contact blobs are off (`src/game/gameState.ts:2352-2355`),
   so a guard past 40 m under open sky has no ground shadow at all; the job lead judges that in the look check and can
   drop rule 2 (its own commits) without touching rule 1.

`?guardsun=0` turns both rules off (A/B measurement, like `?guardmerge=0`).

## Step 1 (commit S6a): the pure helpers + flag
New `src/world/sunCascadeCull.ts` (Babylon-free: `import type { AbstractMesh } from '../core/babylon'` only):
- `export const GUARD_SUN_REACH = 40;` `export const SUN_REACH_HYST = 3;` `export const CASCADE_PAD = 0.5;` (m; covers
  S1's box doubts: raised hands up to 0.3 m outside the rest box) and `export const CASCADE_NDC_PAD = 0.05;` (NDC; the
  cascade blend band, `cascadeBlendPercentage` 0.08, samples the next layer near its edge).
- `export function inCascadeXY(t: ArrayLike<number>, cx: number, cy: number, cz: number, r: number): boolean`:
  `t` is a cascade's view x projection matrix in Babylon's layout (`Matrix.m`, row vectors: `x' = x*t[0] + y*t[4] +
  z*t[8] + t[12]`, `y' = x*t[1] + y*t[5] + z*t[9] + t[13]`, `w' = x*t[3] + y*t[7] + z*t[11] + t[15]`; orthographic, so
  `w'` is 1, but divide by it anyway when it is not 0). Radius in NDC: `rx = (r + CASCADE_PAD) * hyp3(t[0], t[4], t[8])`,
  `ry = (r + CASCADE_PAD) * hyp3(t[1], t[5], t[9])`. Return `|x'| <= 1 + CASCADE_NDC_PAD + rx && |y'| <= 1 +
  CASCADE_NDC_PAD + ry`. No z test.
- `export function keepNearCamera(wasIn: boolean, d2: number, reach: number): boolean`: `reach === Infinity` -> true;
  in when `d2 <= reach * reach`; when `wasIn`, stays in while `d2 <= (reach + SUN_REACH_HYST) ** 2`.
- `export class SunCascadeLists`: holds 4 arrays created in the constructor (`readonly lists: AbstractMesh[][]`, the
  most cascades any preset uses, `quality.ts:124`). `fill(layer: number, src: readonly AbstractMesh[], t:
  ArrayLike<number> | null): AbstractMesh[] | null`: returns `null` when `t` is null or `layer` is outside 0-3 (the
  caller then draws the default list: correct, just not culled); otherwise sets `out.length = 0`, and for each mesh in
  `src` order pushes it when `inCascadeXY(t, c.x, c.y, c.z, s.radiusWorld)` with `s = mesh.getBoundingInfo().
  boundingSphere`, `c = s.centerWorld`; returns `out` (the same array object every call for a layer). Plain indexed
  `for` loops; nothing allocated after the arrays grow once.
- `src/core/flags.ts`: after line 58 (`guardMerge: boolean;`) add the doc line + `guardSun: boolean;`
  ("(guard-render S6) Per-cascade sun caster lists and the guards' sun reach; `?guardsun=0`: off, for comparisons.");
  after line 123 (`guardMerge: ...`) add `guardSun: params.get('guardsun') !== '0',`. Check `grep -n "guardMerge"
  tests src` for a test or a typed flags literal that needs the new key too (add it there only if `tsc` demands it).

New `tests/sunCascadeCull.test.ts` (vitest, node env; Babylon math from `../src/core/babylon` and `NullEngine` from
`@babylonjs/core/Engines/nullEngine` as `tests/helpers/animSkeletonGuardIdentity.ts:75-81` does):
1. A real cascade matrix: light direction (0.3, -1, 0.2) normalised, `Matrix.LookAtLHToRef(centre - dir * 50, centre,
   up)` times `Matrix.OrthoOffCenterLHToRef(-10, 10, -10, 10, 0, 100)` (multiply `view.multiply(proj)`, Babylon's
   order), centre (5, 0, 5). Points: the centre (in), 9.9 m along the light-space x axis (in), 12 m (out unless
   `r` reaches: test r = 0.2 out, r = 2 in), a point 30 m behind the near plane along the light ray but inside x / y
   (in: no z test).
2. Exactness, randomised (seeded loop, 500 cases): random sphere centre / radius; whenever `inCascadeXY` returns false,
   64 points on that sphere's surface (seeded directions) all project with |x'| > 1 or all with |y'| > 1, on the
   same side (so a caster inside the sphere writes nothing into that layer). Never a false negative.
3. `keepNearCamera`: Infinity always true; 39 m in; 41 m from out stays out; 41 m from in stays in; 43.5 m from in
   goes out; exactly 40 m in.
4. `SunCascadeLists.fill` with `NullEngine` boxes (`CreateBox` via `src/core/babylon.ts`, `computeWorldMatrix(true)`
   after placing): keeps `src` order, drops the outside ones, returns the same array object on a second call, returns
   null for `t = null` and for layer 4, an empty `src` gives an empty list.
